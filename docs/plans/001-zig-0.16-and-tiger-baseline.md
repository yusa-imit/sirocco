# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Put sirocco on Zig 0.16.0 with CI green, install a `tidy` build step so Tiger Style is enforced
mechanically from the first line of real code, and re-aim `docs/PRD.md` at `std.Io.VTable` so
Phase 1 is not built against a design 0.16 has already obsoleted. No runtime code lands here.

## Why now

sirocco is 187 lines across 8 files: six `error.NotImplemented` stubs plus a CLI. The 0.16 probe
found 2 surfaced errors (~7 latent call sites) in two entry points and no blocking dependencies
— the kingdom's cheapest migration, and it must land before Phase 1 or every Phase 1 file gets
written twice. The design reason is larger: 0.16's `std.Io` *is* the completion-based,
cancelable, vtable-dispatched runtime sirocco set out to build, so the old kqueue-abstraction
PRD would ship an API no consumer speaks. And every Tiger Style counter in STATE.md reads 0 only
because no code exists — enforcement must precede the code.

## Out of scope

- Phase 1 runtime code — completions, backends, timing wheel, loop dispatch; the first vtable
  slot opens plan 002, written against the rewritten PRD. Also out: a native macOS CI lane
  (kqueue will need one; see Risks), io_uring/IOCP backends, and consumer integration — nothing
  here is importable yet.
- 0.16 classes absent from this repo: `build.zig` `linkLibC`/`linkSystemLibrary` (build.zig
  compiles clean as-is), `std.net`, `Thread` sync, `ArrayList{}` → `.empty`, `indexOf*` →
  `find*`, `@Type`, `Smith`. They arrive with Phase 1; `tidy` and the PRD keep them 0.16-shaped.

## Risks

- **Green proves nothing yet.** Every Tiger Style counter is 0 because no functional code exists
  (STATE.md), so `tidy` on 187 lines of stubs shows only that the gate runs; the
  injected-violation check in item 2 is the real test.
- **The probe undercounts.** 2 errors is one per binary — the compiler stops at the first, and
  ~7 call sites are latent. Mitigation: items 3 and 4 are per-file and each ends in a run.
- **macOS is uncovered.** Tests are Linux-only because 0.15 macOS images could not link
  libSystem, and cross-compiling catches no runtime backend bug while kqueue is macOS-only.
  Mitigation: re-test whether 0.16 fixes the link failure; do not chase it in this plan.
- **The PRD rewrite is a design decision, not an edit.** It invalidates most of
  `000-inherited.md` Phases 1–5, and leaving both standing lets a later cycle follow the obsolete
  checklist. Mitigation: item 7 annotates 000 in the same PR.
- **Consumer expectations are unfounded.** Five realms are listed as depending on a runtime that
  does not exist; the README fix is the only honest signal available until plan 002.

- `grep -rn Cancelled src docs` is empty; every file in `src/` and `bench/` opens with `//!`.
- `docs/PRD.md` describes a `std.Io.VTable` implementation (names `Io.failing` and the

## Version impact

**none** — MINOR at 0.x: `0.1.0 → 0.2.0`. sirocco has no released tag and no consumer imports
anything from it (all public API is `error.NotImplemented` stubs), so the migration breaks no
signature: `citadel/protocol/VERSIONING.md` reserves MAJOR for a break in a consumed API.
